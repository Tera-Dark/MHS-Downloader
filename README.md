# MHS-Downloader 0.8.0

**米画师页内浮动面板 + Windows 本机下载引擎。**

从 Hybrid 0.7.1 重构而来。这一版不再提供 `hybrid.html` 独立控制台：连接、选择来源、数量设置、任务控制、补扫、导出及诊断都在米画师页面右下角的 **MHS** 面板完成。

> 此 ZIP 是本地项目交付，不代表已发布到 GitHub。不是米画师官方产品，也不是 XHS-Downloader 的官方分支。已做合成页面和真实 Chromium 扩展测试，**尚未在你的登录会话、真实米画师列表或 Windows 上执行验收**。

## 这次改了什么

- **配对不启动**：令牌只负责连接。来源初始为空；必须点击“使用当前页”或自行粘贴，然后“开始新任务”。同来源重复提交只提示已有任务，不偷偷恢复。
- **旧任务不自动复活**：本机启动时暂停历史活动任务；浏览器重启后，页面采集器也需要手动继续。保留文件与检查点。
- **作品、图片分别限量**：默认最多 100 幅 / 100 张，任一上限触发就停止新增。可分别改成 0；0 仍受 5,000 幅 / 10,000 张安全上限约束。
- **更快发现作品**：优先读取已挂载作品组件和已加载列表中的作品 ID，直接打开详情，不必逐卡点击再返回。没有可用 ID 时才回退到普通点击。
- **不再把“DOM 数量不变”当成扫完**：累计保存发现过的作品；检测嵌套滚动容器、虚拟列表和加载状态；到底后静默观察；不完整时递增等待并有界重扫。
- **两种进度分开显示**：发现 `14 / 91` 与保存 `14 / 14` 不再混为“完成”。数量上限、补扫等待、扫描不完整、文件失败分别显示。
- **可调整的恢复策略**：自动补扫 0–5 次，默认 3；解析/网络文件重试 0–5 次。设置可在已有任务内修改，“保存设置并继续”是明确的启动操作。
- **操作记录可追溯**：看到任务来源、启动时间、手动继续和自动补扫记录；诊断信息不包含配对令牌或 Cookie。
- 保留 SQLite 队列、校验过的 Range 续传、SHA-256/原子落盘、完成文件复用、ZIP/链接快照导出。没有强制授权勾选。

## 首次使用

1. 解压整个 `MHS-Downloader` 文件夹，不要在 ZIP 内直接运行。
2. 双击 **`START-WINDOWS.bat`**。首次会建立 `.venv` 并安装依赖。保持本机窗口打开。
3. Chrome 打开 `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选择本项目的 **`extension`** 文件夹。
4. 打开或刷新 `https://www.mihuashi.com/`，点击右下角 **MHS**，进入 **连接与设置**。
5. 将本机窗口显示的完整令牌粘贴进去，点击 **连接本机 · 不启动采集**。应看到绿色连接状态和明确成功提示。
6. 进入画师主页或作品详情页。在 **采集作品** 点 **使用当前页**，或粘贴链接；设置数量和节奏；最后点击 **开始新任务**。
7. 在 **任务** 查看发现、解析、保存进度。可暂停、继续、补扫、重试、修改限制、导出 ZIP/链接、打开目录、查看错误和诊断。

快捷键：**Alt+M** 打开/收起；页面上的 **Esc** 可收起。Chrome 工具栏图标也可唤起页内面板。直接打开扩展内部 `panel.html` 不提供独立控制能力。

### 你已经安装的 Python 3.12

启动器会优先检查常见安装位置，包括：

```text
C:\Users\wjx19\AppData\Local\Programs\Python\Python312\python.exe
```

**不要求安装 `py`，也不要求先重装 Python。** 如需明确指定，可在 CMD 中运行：

```bat
set "MHS_PYTHON=C:\Users\wjx19\AppData\Local\Programs\Python\Python312\python.exe"
START-WINDOWS.bat
```

`ARCHIVE_PYTHON` 仍兼容旧配置。Python 要求 3.11+；本版目标环境是 Windows + Chrome 120+。

## 从 0.7.1 升级：先保留 data

详见 **[升级与数据保留](docs/UPGRADE.md)**。最重要的四点：

1. **关闭旧本机程序，禁用或移除旧 Hybrid 扩展**，避免两个采集器同时运行。
2. **不要删除 `data`**。先备份，随后把整个旧 `data` 复制/移动到新项目下，或通过 `MHS_DATA` 指向旧数据目录。
3. 加载新版 `extension`，刷新米画师页面并重新配对。不要继续打开旧 `hybrid.html`。
4. 历史任务会显示为暂停；核对来源与上限后，点击“继续”或“保存设置并继续”。

引擎识别到旧版数据库时，会在修改前创建一次 `data/archive.pre-0.8.0.sqlite3` 一致性备份；这只备份数据库，**不能替代对整个 data 的备份**。

## 数量与节奏的准确含义

| 设置 | 默认值 | 范围 / 说明 |
|---|---:|---|
| 最多作品 | 100 | 0–5,000；按发现顺序入队，不承诺按发布时间排序 |
| 最多图片 | 100 | 0–10,000；**按图片入队记录计数**，不是成功下载数量 |
| 下载并发 | 3 | 每任务 1–4；本机全局最多 4，详情解析仍是单独顺序队列 |
| 页面间隔 | 1.5 秒 | 1–10 秒；限制新页面访问，不是文件流速度 |
| 自动补扫 | 3 次 | 0–5；首次失败后约 8、16、32…秒等待，最多 120 秒 |
| 解析/文件重试 | 3 次 | 0–5；首次尝试之外的额外重试；格式错误等永久错误不会盲目重试 |

- 一幅作品可能含多图。已发现作品很多，也可能先达到图片上限。失败记录占用预算；不会通过不断换图绕过你设定的上限。
- 调高图片上限后，受限的同一幅多图作品也可重新解析、补入余下图片；已完成记录不重复新增。
- 调低上限不能低于已有发现数/图片记录数，不会为满足新数字删除旧数据。
- 识别到预期总数且未扫足时，保持“不完整”；触及用户上限则显示“已到数量上限”，不无限补扫。
- 没有页面总数时，只能依据到底、静默与加载状态判断，不能保证绝对完整。
- 登录、验证、页面 401/403 和 429 会拦截；需要人工检查官网，再点击“官网已恢复，解除拦截”。有效的服务器冷却时间不能提前解除。

## 停止、继续与保存

| 操作 | 实际行为 |
|---|---|
| 连接/检查版本/刷新状态 | 不创建任务，不改变任务启动状态，不启动页面采集器 |
| 收起面板或离开控制面板所在页面 | 已明确启动的任务继续 |
| 暂停单项 / 暂停全部 | 停止该项 / 全部新增采集及传输；保留部分文件和检查点 |
| 关闭 Chrome | 页面解析停止；**已入队的本机文件下载仍可继续** |
| 重开 Chrome | 令牌保留，页面采集器不自动恢复；需手动继续 |
| 关闭并重开本机程序 | 历史活动任务暂停，部分传输重新入等待；需手动继续 |
| 归档 | 从默认任务列表隐藏，不删除图片；勾选“显示已归档”可查看 |
| 导出 | 导出当前快照，不等同于任务完整完成；文件在 `data/exports` |

配对本身不会启动或停止此前已由你明确启动的本机传输。如果想确保所有环节停止，先点击 **暂停全部**。

## 关于“只粘贴令牌就开始抓取”

没有在生产代码中找到你截图中的画师 ID，也没有内置默认采集目标。旧版确实存在“本机启动恢复活动任务 + 扩展拿到令牌后轮询旧队列”的行为，这能解释历史目标自动继续的现象；未拿到你的数据库，不能断言这是那次现象的唯一原因。

本版用默认暂停、空来源、显式启动、浏览器会话启动标记和操作记录消除这一触发链，不通过清空历史记录来掩盖问题。

## 边界与故障处理

- 当前只支持 `www.mihuashi.com` 的 `profiles/数字`、`users/标识` 主页和 `artworks/数字` 详情。是普通页面解析，不使用私有 API 签名、Cookie 导出或验证绕过。
- 保存的是**详情页实际展示图**，不是猜测或保证的原始上传文件。不通过去除 CDN 后缀“构造原图”。
- 展示图沿用较大图片过滤（宽高至少 400、面积至少 360,000 像素），每详情最多 30 候选；极小尺寸作品、复杂画廊或改版结构可能需要人工处理。图片文件还受解码与大小安全限制。
- 如果持续停在不完整，查看任务的滚动容器、静默时长和操作记录，点“显示诊断 JSON”复制给开发者。耗尽自动补扫后不会伪装完成。
- 本机不可连接：先排除旧程序占用 47653，确认 BAT 未退出；更新两个部分、重新加载扩展和刷新站点；检查浏览器本地网络权限。
- 本机 API 仅监听 `127.0.0.1:47653`，校验 Host、配对扩展身份与令牌。不要公开端口、令牌或包含私人画作的诊断。
- 不要把本机服务绑定到公网，也不要修改为关闭 TLS 校验。
- 任务面板显示最近 100 项任务（含历史）；导出记录最近 30 项，操作记录最近 40 项。完整队列仍在 SQLite。
- `--port` 供开发测试使用；成品扩展固定使用 47653，不支持只修改服务端端口后直接连接。
