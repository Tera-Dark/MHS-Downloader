# 0.7.1 验证记录

日期：2026-09-15。环境为 Linux 沙箱，**不是用户的 Windows**。

## 本次重点：真实浏览器，而不只模拟 API

使用 Playwright 驱动 Chromium 151.0.7922.34，实际通过 Manifest V3 加载本项目扩展；本机服务运行于 `127.0.0.1:47653`。

### 缺陷复现

0.7.0 的配对 POST 请求返回 200，而 GET 状态请求被拒绝，界面显示未连接。已确认真实浏览器请求差异：POST 有 `Origin`，GET 可以没有。

0.7.1 明确传输扩展标识，并在保留令牌、已配对客户端及 Host 校验的前提下兼容缺少 Origin 的请求。

### 浏览器回归场景

1. 不需要令牌的服务版本自检。
2. 错误令牌在按钮旁显示 `TOKEN_INVALID`。
3. 正确令牌的 POST 配对与随后 GET 状态读取成功。
4. 无许可勾选即可添加任务，显示成功提示和队列记录。
5. 通过真实 DOM 适配器读取本地模拟主页/详情，直链记录写入 SQLite。
6. 点击暂停后按钮更新，不因焦点而显示旧状态。
7. 关闭重开控制台后，连接与任务仍可读取。
8. 上述流程没有 UI JavaScript 异常。

第 5 项使用拦截后由本地返回的测试 HTML 和生成的 PNG，不访问实际米画师，不验证实际 CDN 下载。测试代码用显式状态轮询确认 `works.ready=1` 和 `files.link=1`，不把返回 Promise 本身当作条件成功。

浏览器脚本：`tests/browser_smoke.py`。需要额外安装 Playwright 和 Chromium；只对空的临时测试数据目录运行，不能对真实归档队列运行。
