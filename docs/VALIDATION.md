# 0.8.0 验证记录

日期：2026-09-15。执行环境：Linux、Python、真实 Chromium 151.0.7922.34 扩展上下文。没有使用用户真实数据目录。

普通使用不需要 Node.js 或 Playwright。以下命令仅供开发者复现测试，并需在已安装 `native/requirements.txt` 的 Python 环境中执行。

## 自动测试

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

**62 项通过**，由 23 项原传输/引擎回归、19 项实际 HTTP API 集成和 20 项新队列策略测试构成。

覆盖重点：

- 严格图片域名和重定向检查；200 不能追加；206 必须匹配 Content-Range、长度和实体校验；416 清理不匹配部分文件。
- 中断文件重启后先暂停，再明确继续并完成；实际图像解码、哈希、原子文件保存与 ZIP 清单。
- Origin 可缺省的合法扩展 GET；令牌、Host、配对身份、恶意网页来源和伪造扩展标识拒绝。
- 新建默认暂停、缺少来源拒绝、重复提交不恢复、引擎重启暂停并保留旧检查点。
- 旧数据库修改前创建一致性备份，备份仍为旧 schema/原状态，新库任务暂停。
- 并发提交下原子的作品/图片上限；0 的行为；触及上限不当成扫描失败。
- 14/91 不完整扫描的递增等待、有界耗尽、自动恢复后 ID 去重；设置为 0 可关闭补扫。
- 暂停/继续后的旧 revision 结果拒绝；缺失 revision 不接受；每任务下载并发约束。
- 调高图片上限后可补入同一幅多图作品的剩余图片；不能通过调低上限删除旧记录。
- 归档保留文件，诊断和操作记录保留启动原因。

## 真实浏览器：不是模拟 runtime 的 UI 测试

安装测试依赖后，先关闭占用 47653 的本机程序：

```bash
python -m pip install playwright
python -m playwright install chromium
python tests/browser_smoke.py
```

Linux 如缺系统库，再按 Playwright 提示安装依赖。测试自己启动临时本机服务、创建临时浏览器配置并在结束时关闭；若已有服务占用端口，会拒绝执行，不向现有归档写入假数据。

已通过的场景：

1. 在合成米画师页按 Alt+M 打开**真实加载的扩展 iframe**；输入错误令牌有反馈，正确令牌完成 POST pair 和 GET state；随后没有 GET next、没有任务、没有默认来源。网页拿不到 closed ShadowRoot，令牌没有写入宿主页面 HTML。
2. 点“使用当前页”后显式创建任务；后台标签页实际执行 DOM 扫描和详情解析，经过 POST discovery / POST parsed，最终在本机 SQLite 留下 ready 作品及 link 图片记录。
3. **14/91 → 91/91**：嵌套滚动容器、只挂载 5 张卡片的虚拟列表、下一页延迟 **12 秒**。累计发现完整 91 个 ID，过程中 **没有逐卡点击导航**。
4. **实际自动补扫**：首轮无加载信号却只有 14/91，静默后标记不完整；本机记录补扫等待；到期后浏览器重新加载列表，第二轮恢复到 91/91。断言有 rescan_scheduled / auto_rescan 操作记录，未靠手动重扫触发。
5. 页内修改已有任务并发并“保存设置并继续”；点击 ZIP 导出，实际本机文件生成，UI 显示导出状态。该浏览器场景是 links 模式，ZIP 为链接任务快照；含图片 ZIP 由传输单测覆盖。
6. 暂停全部后刷新页面，连接和历史保留、来源仍为空；单独打开 panel.html 被拒绝操作；UI 没有 JavaScript 异常。
7. 先明确启动任务，再**实际关闭和重启 Chromium**、保留浏览器 profile/令牌。本机仍在线、有活动历史；重启后采集器未启动，也未请求 GET next，必须手动继续。

日志：`native-tests.log`、`policy-tests.log`、`browser-tests.log`。浏览器日志只记录方法和接口路径，不记录 Authorization、Cookie 或令牌。
