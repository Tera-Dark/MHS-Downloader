# 0.5.0 用户流程、架构与风险审查

日期：2026-09-14。审查对象为 0.4.0 代码与普通用户流程，修复交付为 0.5.0。

## 结论先说

**小规模、获许可的本地作品整理场景下，现有架构方向可用；但不能因为主流程跑通，就把它称为没有隐患的成熟采集框架。** 本次发现并修复了恢复、导入、持久化、重复工作台和访问暂停方面的缺口。没有新增采集站点、扩展权限或规避风控能力。

界面不再继续堆功能入口：压缩宣传区域，扩大队列，增加关键异常提示，隐藏无内容预览，并明确“已下载数量”不等于“已收集数量”。

本记录属于源码审查、浏览器用户路径回归和故障注入，不是第三方渗透测试，也不是对用户 Windows 登录环境或实站 91 件作品的验收。

## 按用户路径检查

| 用户步骤 | 检查和处理 |
| --- | --- |
| 初次加载、已有记录升级 | 用最终 ZIP 解压目录在全新配置加载；覆盖记录恢复与旧来源 JSON 导入。没有实际点击 Windows 扩展安装界面 |
| 主页浮动入口 | 未确认许可不能启动；可以后台收集、下载、解析直链、停止、拖动与隐藏 |
| 收集完整性 | 36 件模拟懒加载列表收集完整，原页面地址、位置和活动标签页不变；部分结果不自动下载 |
| 预览再下载 | 复用 10 分钟内的就绪候选，减少再次打开详情页；重置会清除候选 |
| 下载与去重 | 保留并发、ZIP 分卷、SHA-256 去重、CRC/实际图片字节、原生下载检查 |
| 停止及恢复 | 保留已有缓冲的手动保存；未确认下载恢复增加归属校验，不能只信数字 ID |
| 备份和迁移 | 保留有效候选；无效条目跳过并报告；无有效成功图片不信任空 `done` 标记 |
| 磁盘/存储异常 | 注入扩展存储失败，验证提示、控件恢复与紧急备份可用；本次不是实际磁盘耗尽测试 |
| 工作台被关闭或改作其他页面 | 生命周期锁阻止重复实例；失效登记不会把用户复用的网页强行改回工作台 |
| 网站拒绝访问 | 新增持久化保护暂停与 Retry-After 等待；重开工作台或倒计时结束均不自动发起请求 |

## 已修复的主要问题

P1 为可能影响数据或访问边界的优先项，P2 为可靠性/体验项；不是第三方 CVSS 安全评分。

| 优先级 | 发现 | 0.5.0 处理 | 证据类型 |
| --- | --- | --- | --- |
| P1 | 恢复未确认下载时只按 ID 检索，存在误认或取消无关记录的风险 | ZIP 核对本次下载来源；原生核对原 URL 和文件名；无法确认则标记未确认，不取消。导入记录不用于直接定位/取消 | 代码审查＋冲突下载记录故障注入＋纯规则测试 |
| P1 | 重复工作台在初始化阶段仍有竞争可能 | 从初始化前到页面关闭持有独占 Web Lock；异步访问检查前预留操作互斥 | 浏览器重复文档与并发操作测试 |
| P1 | 本地保存失败可能发生在收尾阶段，界面仍显示忙碌或让用户误以为已保存 | 保存调用时的状态快照；显示未保存警告，释放控件，保留内存备份入口 | 存储配额错误注入 |
| P1 | 顶层本地记录结构异常没有专门恢复入口 | 拒绝初始化、不覆盖原记录，提供原始恢复副本 | 损坏结构、字节内容与备份验证 |
| P1 | 遇限制停止后，用户重开工作台即可再次误点开始 | 将访问暂停保存在本机；429 参考 Retry-After 且至少等待 60 秒，人工解除后仍需手动开始 | 实际模拟 HTTP 429 响应、重载、人工解除测试 |
| P1 | ZIP fetch 在跟随跳转之后才核对最终域名 | 使用拒绝重定向策略，退出时终止响应；不在存储暂停失败时阻断即时停止信号 | 模拟 302 请求未到达后续地址；停止信号写入路径审查 |
| P2 | 导入会丢失已解析候选，异常元素还可能中断导入 | 先规范化与核对容量；保留有效候选与时间；报告跳过的无效记录 | null、候选保留、空成功标记回归 |
| P2 | 预览后下载/解析可能重复读取同一详情页 | 复用短期就绪候选，过期或重置后才重新读取 | 详情页请求次数检查 |
| P2 | 工作台登记的标签页被用户导航到其他网站后仍可能被当作工作台 | 用内部探针判断登记是否有效，失效时另开工作台，不修改用户原页 | 浏览器导航与新工作台创建测试 |
| P2 | 宣传空间、空预览和含糊的计数占用注意力 | 紧凑标题、扩大队列、状态栏置顶、提高小字对比度、空队列禁用下载、空预览隐藏 | 浏览器断言与实际界面截图检查 |

以上没有声称用户此前确实丢失或误删了文件；风险由代码路径和模拟冲突证明，不等于已经发生过真实损害。

另修正了一个停止后的操作阻碍：保存已取得的 ZIP 缓冲是纯本地动作，不再要求重新勾选网络采集许可；测试确认这一步没有新增网站请求。

## 架构是否合理？

### 保留的合理部分

- MV3 扩展复用用户正常浏览器环境，不索取 Cookie/密码，不另造登录系统。
- 页面 DOM、工作台、后台消息和 ZIP 工具已有基本职责边界；运行时不需要 Node/Python。
- ZIP 保存完成才确认成功，存在来源、哈希与分卷记录，优于只靠文件名判断成功。
- 独立任务页避免在原主页反复滚动/跳转，后台部分结果由用户确认。
- 测试、文档、设计源文件和可确定性打包可以随仓库复现。

### 本轮调整

新增 `core-policy.js`，把 URL 边界、导入规则、下载归属、候选复用和 Retry-After 解析提取成可独立测试的纯规则。工作台增加生命周期所有权与单次操作互斥；保存采用调用时快照。

**仍未完全解耦。** `manager.js` 仍约 1700 行，任务调度、扫描、下载和 DOM 操作仍共享状态。建议下一阶段按测试保护的接口拆分 `TaskService / DownloadService / StateStore`，而不是为了“看起来工程化”立刻引入大框架重写全部逻辑。

## “防反爬”是否完善？

准确说，本项目提供的是**限流、避免重复请求、识别限制后停止与人工确认**，不是反检测或绕过机制。

已具有：

- 页面间隔、有限并发、作品数量与图片/分卷限制；遇失败不自动切账号、换代理或重试。
- 先滚动批量收集链接，再处理无链接卡片；短期候选复用减少重复打开详情页。
- 可观察的 401/403/429 和已知登录提示进入持久化暂停；429 使用 Retry-After，缺失或无效时至少 60 秒。
- 等待结束不自动请求；人工解除也不自动请求。暂停期间仍可保存已取得的 ZIP 缓冲。
- 原生下载的明确拒绝/未授权错误也会暂停，但不把所有原生错误猜测为某个 HTTP 状态。

仍不能保证：

- 不封号、不会触发限制、等待某段时间后一定可用。
- 覆盖所有验证码、软性限制、200 响应中的验证文案或未来页面改版。
- 控制网站自身所有请求、异步弹窗、预加载及浏览器原生下载的全部跳转/响应头。
- 凭本机模拟结果证明真实画师主页完整可用。本轮没有重新请求此前返回 403 的主页。

## 保留的风险与下一步

| 风险 | 当前边界 / 建议 |
| --- | --- |
| 关闭浏览器或工作台丢失未保存缓冲 | 已明确提醒、支持当前会话手动保存；没有承诺持久化图片断点恢复。后续可评估分块落盘及日志式状态存储 |
| 大图解码与多卷内存峰值 | 单图字节及已知像素限制不等于对所有解码炸弹的防御；ZIP Blob、下载并发和页面本身会叠加内存，未完成生产大容量压力测试 |
| 超大任务记录与频繁整份写入 | 5000 件上限不是性能认证；快照增加可靠性但也有复制开销。后续应做 IndexedDB/增量持久化和批次归档评估 |
| 深层损坏数据与不可信备份 | 本次覆盖常见结构和容量检查，不是穷尽格式 fuzz；完整备份仍包含私密来源资料，不能当作可信公开数据或文件存在证明 |
| 原生下载限制可观测性 | ZIP 模式控制较强；原生模式由浏览器处理，无法保证读到每一次 HTTP 429 和 Retry-After，也无法像 fetch 一样禁止全部跳转 |
| 缓存链接过期 | 10 分钟只是复用窗口，不是站点有效期保证；失败停止，人工检查后重置，不自动刷新签名或猜地址 |
| 后台节流与实站虚拟列表 | 仍需持有许可的 Windows Chrome/Edge 实机小批量验收；不保证浏览器休眠或被回收后继续 |
