# v0.3.1：主页扫描导航修复与验证

日期：2026-09-14。此前结果保留在 [0.3.0 验证记录](verification-0.3.0.md)，本页只记录此次补丁实际执行情况。

## 用户报告与定位

用户从画师主页浮动按钮进入工作台，点击扫描后停在具体作品页；截图日志包含 `No tab with id: 0`、`Cannot find a next_page in history.` 和“页面跳转或要求登录”，扫描显示保留 0 件。

截图布局看起来属于旧界面，但 0.3.0 仍保留了同样的导航依赖，不能只以“升级到 0.3.0”作为解决方案。

源码确认了两项缺陷：

1. 无普通链接的卡片需要常规点击获取作品 URL。旧代码先后退并等主页恢复，再把 URL 加入队列；若后退失败，已经识别出的 URL 也不会入队。
2. “使用所选页面”未检查空选项，`Number('')` 会得到 0，继而向浏览器请求不存在的标签页 0。

旧错误文案把地址不匹配和“要求登录”混为一谈。截图不能证明未登录，也不能证明该实站使用的是哪一种路由实现。

## 先复现，再修复

使用未修改的 **0.3.0 最终安装 ZIP** 解压目录，在本地模拟主页点击普通卡片进入作品页，并在测试中让 `chrome.tabs.goBack` 抛出与截图相同的历史错误。

实际复现结果：已进入作品页，但扫描停止，`found: []`，队列为 0。该实验确认旧代码在同款错误下确实丢失本轮刚找到的链接；它不是对用户电脑或真实站点内部路由的远程调试。

本机证据保留在 `artifacts/navigation-before-fix/`，不把用户截图、真实图像或浏览器数据纳入源码包。

## 补丁行为

- 先保存已发现作品 URL，再返回主页。即使返回彻底失败，也保留链接和准确的已收集数量。
- 先尝试正常后退。仅在缺少历史或地址未回到预期主页时，对已知公开作品页、主页或空白页执行一次原主页地址恢复。
- 恢复列表时有界重放滚动；无法恢复则停止，不无限刷新。点击及返回遵守设置的页面间隔。
- 未知重定向、真正的登录/验证弹窗及 HTTP 401 / 403 / 429 不属于导航恢复理由，仍需停止。
- 空选项先提示选择，已失效标签页提示刷新列表；不再把空字符串转换为标签页 0。
- 导航错误与登录错误分开显示。

保留之前 27 个浏览器检查点，新增 6 项：

1. 空下拉选择不向浏览器请求标签页 0。
2. 点击生产浮动按钮，把主页带入工作台；不会自动启动扫描。
3. 模拟 SPA `history.replaceState` 和 `location.replace` 卡片：恢复原主页并收集全部 2 件作品。
4. 注入截图中的历史错误：按原主页地址恢复一次，完成扫描；核对主页请求只有初次打开和这次恢复。
5. 注入无法恢复的返回错误：停止，但已识别的 1 件作品留在队列和扫描记录中，不再显示保留 0 件。
6. 点击卡片后遇到明确登录提示：停止扫描，不通过重新打开主页绕过提示。

第一、二轮报告分别在本机 `artifacts/release-031-round-1.json` 和 `artifacts/release-031-round-2.json`。测试脚本仍为 `tests/e2e/run.py`，复现命令见 [开发指南](development.md)。

- 本轮没有重新请求此前返回 403 的真实主页，也没有声称已采集该画师的 91 件作品。
- 没有在用户的 Windows 浏览器、真实登录会话或所有 Edge 版本上验证。
- 新增测试覆盖的是能够复现截图症状的导航类型，不代表所有真实卡片、异步弹窗、登录态和懒加载实现均已覆盖。
- 仍不是大容量、多小时压力测试；也不保证原稿、全站兼容或账号绝不受限。

## 用户升级要点

先导出旧任务备份。加载 0.3.1 后关闭旧工作台、重新打开并刷新官网页面。如果新旧扩展并存，请暂时禁用旧版，避免点击旧内容脚本的浮动按钮。

确认工作台顶部版本为 **0.3.1**。粘贴主页地址、确认许可，点击“收集这个主页的作品”。不需要逐个“添加此作品”；也无需在粘贴地址后再使用页面下拉框。

如果仍在第一件作品停止，请保留新的扫描结果和原始错误，停止连续尝试，再据新的证据定位。不要提供 Cookie、密码或完整浏览器用户目录。
