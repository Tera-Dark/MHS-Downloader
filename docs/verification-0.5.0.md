## 本次新增的 13 个检查点

在此前 43 个流程检查的基础上，增加：

1. 空预览不占界面空间，空队列下载操作禁用。
2. HTTP 429 的 Retry-After 暂停跨工作台重开保留，不发起自动请求。
3. 到期后人工解除暂停，也不自动恢复请求。
4. 导入跳过 null、保留有效候选，不把空成功标记当成已下载，无网络请求。
5. 复用新鲜候选，不重新打开详情页。
6. 恢复时不确认或取消只有数字 ID 相同的无关下载。
7. ZIP fetch 遇 302 不跟随后续地址。
8. 存储失败可见、不把控件永久留在忙碌状态，仍能导出内存备份。
9. 生命周期锁阻止重复工作台初始化/改写状态。
10. 异步检查之前串行化同时开始的操作。
11. 工作台旧标签页改作其他页面后，另开正确工作台，不劫持用户复用的页面。
12. 原生下载明确拒绝错误也形成需人工解除的访问暂停。
13. 损坏的顶层本地记录保留原样，可导出原始恢复副本。

原有路径仍覆盖：浮动入口、许可、后台滚动收集、36 件懒加载列表、原页面位置/活动标签页保持、两种下载方式、直链解析导出、停止与缓冲保存、卡片导航恢复、队列搜索分页、按所选范围下载、ZIP CRC/SHA-256/实际尺寸、内容去重、导入恢复及诊断白名单。

## 故障注入范围

- 429 来自本地服务器实际响应，附带 `Retry-After: 120`。独立场景之间显式清理测试保护状态；到期解除测试只修改模拟截止时间，不在发行 UI 中提供跳过倒计时功能。
- 下载记录冲突、存储配额、原生拒绝错误通过测试中的 API 替身注入；不是在用户电脑删除、取消或耗尽真实磁盘。
- ZIP 重定向使用真实本地 302 响应；日志里的该请求 `net::ERR_FAILED` 是预期的拒绝跳转，不是未捕获异常。
- 原始恢复测试临时写入损坏顶层结构，检查没有被空状态覆盖，再核对导出的恢复 JSON，最后还原测试数据。
- 已有分卷测试仅在测试中降低阈值，不代表生产 64/128/256 MB、多小时压力测试。
